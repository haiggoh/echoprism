## Tasks

### Task A — local stream proxy for headered URLs (fixes the Stream error)
**Files:** new `src-tauri/src/stream_proxy.rs`; `src-tauri/Cargo.toml` (add `hyper = "1.12"` server+http1, `hyper-util = "0.1.21"` tokio, `http-body-util = "0.1.5"` — all already in Cargo.lock); `src-tauri/src/lib.rs` (mod); `src-tauri/src/extractor/mod.rs` (`get_stream_with_yt_dlp`).
- `stream_proxy`: lazy global (`OnceLock`) hyper server on `127.0.0.1:0`; `register(url, headers) -> token` stores in a DashMap; `GET /stream/{token}` forwards the request (incl. `Range`) upstream via reqwest with the stored headers and streams the body back, copying status/content-type/content-length/content-range/accept-ranges.
- Extractor: `get_stream_with_yt_dlp` parses `-J` JSON formats (new serde struct: url, http_headers, format_id, ext, vcodec, acodec, abr, height); picks audio (vcodec=="none", max abr) or video (both, max height); if `http_headers` non-empty → `stream_proxy::register` → return `http://127.0.0.1:{port}/stream/{token}` with headers None; else direct URL as today.
- Tests: stub yt-dlp script emitting `-J` JSON with `http_headers` → returned URL is 127.0.0.1 proxy; without headers → direct. Proxy round-trip test with a local TcpListener "upstream" asserting Range is forwarded and 206 passed back. Live #[ignore] test against real yt-dlp.

### Task D — matcher: sharper patterns, word-level fuzzy, date gate, re-score stale links
**Files:** `src-tauri/src/matcher/mod.rs`; `src-tauri/src/db/queries.rs` (list/update unconfirmed links).
1. `looks_like_branding`: DROP the blanket single-word rule — a segment is branding only if all its words are tag words (livestream/live), it exactly spells a known channel, or it shares a ≥4-char stem with a known channel. "(emotional)" with channels The Verge/Vergecast → NOT branding. Update the round-2 test that asserted None-channel 1.0 (record the refinement in its comment).
2. `similarity_of`: replace char-coverage fuzzy with WORD-level matching — two words match if equal or (shorter len ≥ 4 and fully covered by fuzzy_indices into the longer). Score = matched / union (Jaccard over matched words). "iPhone X Review" vs "iPhone Duo review (emotional)" → x↔duo no match → 0.5 → below gate.
3. Date hard gate: new `MatchingConfig.date_hard_gate_days: Option<i64> = Some(2)` — in `best_pairing`, skip any pair whose dates are both known and differ by more than the gate.
4. Re-score: `match_all` also re-evaluates UNCONFIRMED existing links (new `list_unconfirmed_links`, `update_episode_link_scores`) and upgrades confidence/user_confirmed when `certain` — so the stale 68% Tesla link becomes 100% confirmed on the next Run Matching.
- Tests: false positive rejected (with and without dates); date gate (3 days apart, both known → skipped; ±2 days → allowed); Tesla pair → 1.0 with channels; branding "(emotional)" not stripped; re-score upgrades a stored unconfirmed link; existing calibration/guard tests stay green.
